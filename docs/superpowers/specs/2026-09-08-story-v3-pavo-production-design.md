# 《最后十四天》v3.0 正式剧情与 Pavo 制作包设计

## 目标

在不改变“四条一级路线、十二个二级行动、三十四条独立终局”基本结构的前提下，先完成剧情逻辑的全量复审与修订，再建立唯一有效的 Pavo 制作包。Web 导演地图、文字脚本、制作目录、Pavo 提示词和最终视频地址必须使用同一组节点 ID 与确定结果。

关键帧生成是后续阶段。剧情闸门未通过前，不生成新的关键帧，不向 Pavo 投喂。

## 权威顺序

发生冲突时按以下顺序裁决：

1. 当前用户确认的制作目标与本设计。
2. `短剧制作资料/16_正式剧情树_v2.0/` 中仍然有效的时间、术语和因果规则。
3. `src/demo/redesignedStory.ts` 中当前 Web 使用的三十四条路径数据。
4. 实际成片能看见或听见的事实与真实首尾帧。
5. `01`—`15` 目录中的旧剧本、共享 X 层和旧 F 类结局，仅作为溯源或复用候选，不再拥有现行剧情解释权。

## 固定结构

正式流程保持为：

```text
公共开场 → A/B/C/D 一级路线 → A0/B0/C0/D0 路线局面
        → A1—D3 二级行动及确定后果
        → 路线专属第三次选择
        → 34 条独立结果视频
        → F1—F6 战略画像分类与报告
```

- A、B、C、D 各有三个二级行动。
- 除 D2 外，十一个二级节点各有三个第三次选择。
- D2 是接受出售资料后的不可逆交易，只进入一个自动交付结果。
- 终局数固定为 `11 × 3 + 1 = 34`。
- X1、X2、X3 不进入现行流程。
- F1—F6 只做报告分类，不播放共享剧情片。

## 已确认的剧情修订

### A2 时间与空间

A2 改为“在背风处扎营一夜后的清晨决策点”：第 4 天，剩余 10 天，仍位于可封存设备的背风雪台。现有 A2 营地画面与这一状态一致。

第三次选择的时间依据改为：全队封存非关键设备后轻装前进可在第 13 天提交；资料小组先行也可按时提交；带齐重装并继续等待安全窗口没有可靠的期限余量。不得把角色在同一背风营地凭空写成第 10 天，也不得在尚未越岭时描述为已经抵达背风坡另一侧。

### D1 竞争者状态

D1 只能确认登记窗口关闭、原优先机会终止并进入公开竞争。D0 的报价不能推出竞争者已经获得土地机会。所有“竞争者已经取得机会”改为“当前优先机会终止，竞争者可以参与后续公开竞争”。

### D2 交易标的

D2 的交易对象统一为“完整勘探资料”，包括地图、照片、坐标和勘探记录，不自动包含实体样本。D2-1 表现资料核验、交付、回收大部分投入和永久退出；样本除非在 D0 报价中新增明确条件，否则不得出现在交付清单。

### F5 分类

F5 定义改为“人员与可迁移能力优先的安全撤离型”。它可以发生在主动止损时，也可以发生在窗口关闭后选择人员安全优先时。F6 继续表示窗口关闭后以知识、设备或组织学习为主要目标的重构型结果。

### 成片状态

- A0：已有主体可复用，但缺少背风雪台事实，状态为“部分可用，必须补事实段”。
- B0：使用新版 v4 候选成片；必须通过完整声音与画面复核，确认断桥、检修索桥、轻装限制和重装箱均已建立，验收前不得标记正式完成。
- A1—A3、B1—B3：已有动作主体可复制到新包，但必须按 v3 状态卡补齐第三次选择依据；旧字幕或不确定口播不能直接沿用。
- C0、D0：旧成片仅作人物和构图参考，正式局面必须重做。
- X1—X3 与旧共享 F 类结局：不进入现行剧情，只能放在废弃/参考区。

## 剧情验收闸门

每个节点必须有一张状态卡，明确：

- 进入节点时的位置与时间。
- 行动完成时的位置与剩余时间。
- 人员健康与队长左手状态。
- 文件、样本、设备、补给分别处于什么状态。
- 已建立的外部角色及其权限。
- 玩家作出下一选择前已经看见或听见的事实。
- 每个选项的直接动作、确定结果和不可逆代价。
- 下一段视频的实际输入首帧来源。

全局放行条件：

1. 四条路线、十二个二级节点和三十四条终局数量正确。
2. 每条子路径需要的事实全部出现在父节点状态卡和视频脚本中。
3. 时间只使用“行动完成时”的统一口径，所有移动和等待均有耗时依据。
4. 超期后不再出现赶路、登记或提交选项。
5. 合作运输只出现在 C 路线，竞争者收购只出现在 D 路线。
6. 每条结果使用已经发生的确定事实，不使用“可能、也许、或许”。
7. 不可逆损失不会在后续恢复。
8. Web 数据、路径总表、制作目录和视频文件名的 ID 完全一致。
9. 活跃数据中不存在 X1、X2、X3 或共享 F 剧情视频引用。
10. 自动测试、TypeScript 构建与目录完整性检查全部通过。

只有十项全部通过，剧情状态才能标记为 `story-locked`，并进入关键帧生成。

## Pavo 镜头规则

- 单个 Pavo 源片按 8—12 秒设计。
- 一个源片只承担一个连续空间内的主要动作和至多两句短对白。
- 同一结果需要跨地点、跨日或同时表现“行动 + 到达 + 交付”时，拆为 S01、S02 等连续源片；Web 使用的三十四条结果视频可以由多个源片本地拼接。
- K01 必须来自上一段实际成片最后一帧；K02 是动作和构图参考；K03 是目标尾帧。生成完成后，下一段 K01 必须改用新的实际尾帧。
- Pavo 原片禁止字幕、自动转写、可读文字、UI 和水印。字幕只根据最终音轨单独校时。
- 人物脸型、年龄、发型、服装、背包、阿杰耳机、医疗包、绳索、样本箱和队长左手伤势必须连续。

## 旧素材复制规则

用户确认可以复用的素材采用“复制，不移动，不覆盖”策略：

1. 先计算原文件 SHA-256，并记录原始路径。
2. 经过画面、声音、字幕、首尾帧和剧情事实复核后，标记为“完整复用”“片段复用”或“仅作参考”。
3. 完整复用素材复制进对应节点的 `Pavo原片/`；片段复用素材复制进该节点的 `可复用片段/` 并写明可用时间段；参考素材只进入 `99_旧素材参考_禁止直接投喂/`。
4. 复制不会自动等于验收通过。带错误口播、烧录字幕、水印、人物漂移或错误尾帧的文件必须标记后续处理要求。
5. 不把 X1—X3 或旧共享 F 结局复制进活跃终局目录。

## 废弃标记

旧文件不删除、不批量改名，以避免历史引用断裂。对 `07`、`09`—`16` 中已被替代的入口和共享层增加 `00_已废弃_禁止用于Pavo.md`，至少写明：

- 废弃原因。
- 替代它的 v3.0 路径。
- 是否允许作为人物、构图或动作参考。
- 禁止继续使用的节点、视频或提示词。

`短剧制作资料/01_剧情脚本/README_当前剧本入口.md` 和根 `README.md` 更新为指向 v3.0 唯一入口。旧共享视频在 Web 中不再引用，但在完成引用检查前不移动或删除。

## 验证

新增自动校验应覆盖：

- 34 个终局 ID、34 个唯一 Web 视频地址和 34 个终局目录。
- 12 个父节点目录及其所需文件。
- D2 只有一个自动结果。
- 每个 Pavo 提示词包含无字幕、无文字、无水印、16:9 和连续性约束。
- 每个复制素材都有来源路径、哈希、复用级别和验收状态。
- 活跃制作包与 Web 数据不存在废弃节点引用。
- 剧情校验、项目测试和生产构建均通过。

## 实施顺序

1. 建立剧情状态总表并修复已知矛盾。
2. 逐条审查三十四条路径并更新 Web 数据与自动校验。
3. 生成 v3.0 目录骨架与每节点文字脚本。
4. 审查并复制可复用素材，生成来源清单。
5. 标记旧入口、共享层和旧结局为废弃或参考。
6. 运行完整剧情、目录、测试和构建验收。
7. 用户确认 `story-locked` 后，另行进入关键帧实际生成。
