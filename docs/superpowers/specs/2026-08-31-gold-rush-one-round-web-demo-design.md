# 淘金决策局：一轮四分支 Web Demo 设计

日期：2026-08-31

## 1. 目标与范围

本轮只做一个能直接录屏、给老师快速理解产品形态的桌面 Web Demo：

1. 播放一段第一人称剧情视频，交代高品位金矿、14 天期限、天气和左手伤势。
2. 视频停在队友等待决定的画面，Web 覆盖四个路线选项。
3. 演示者点击任意选项，立即播放该选项独立对应的视频。
4. 视频结束后显示该选择造成的结果、决策类型和三项状态变化。
5. 可直接返回选择页体验其他路线，不重播开场。

不做：扫码、移动端、真实多人投票、登录、数据库、教师后台、历史数据、第二轮决策和完整分支树。

## 2. 方案比较

### 方案 A：数据驱动的一轮四分支状态机（采用）

一个开场视频对应四个选择，每个选择配置独立视频和结果数据。Web 只维护 `开场 → 选择 → 分支视频 → 结果` 四种状态。

- 优点：结构清楚，老师可以现场快速切换四条路线；以后更换 Pavo 视频只改文件名；可以自然扩展第二轮。
- 代价：需要准备四段不同的分支视频。

### 方案 B：四个选项分别写成独立页面

- 优点：编码最快。
- 缺点：重复代码多，后续换视频和扩展节点容易错，不采用。

### 方案 C：直接建设完整多轮分支引擎

- 优点：一步到位支持完整课堂游戏。
- 缺点：超出本次演示范围，会把时间耗在树结构、投票和报告上，不采用。

## 3. 剧情与四个分支

### 公共开场

把已经生成的帐篷剧情按顺序播放或合并为一条开场视频：发现金矿 → 只剩十四天 → 翻山与山谷时间 → 48 小时天气不确定 → 左手伤势 → “队长，决定吧”。

第一处选择应在 45–60 秒内出现。日期、选项、状态和结果全部由 Web 渲染，不让视频模型生成文字。

### 选项映射

| 选项 | 决策类型 | 分支视频内容 | 结果页重点 |
|---|---|---|---|
| A 再等 3–4 周安全撤离 | 保守型 | 队伍在营地等待，天气转好，但远处出现土地拍卖/竞争提示 | 人员安全；矿权失去；时间超期 |
| B 立即翻山 | 激进型 | 队伍进入山脊，暴风提前，左手失力，仍向前推进 | 时间最优；安全风险高；设备可能损失 |
| C 走山谷 | 稳妥型 | 队伍沿山谷行进，道路稳定但路程漫长，期限不断逼近 | 安全较高；时间临界；矿权不确定 |
| D 等待 48 小时预报 | 观望型 | 帐篷外天气恶化，预报确认暴风，队伍获得信息但损失两天 | 信息增加；时间减少；需要再次决策 |

本 Demo 不继续展开 D 的二次选择，只在结果页明确显示“获得信息，但决策并未消失”。

## 4. Web 交互流程

```text
启动页
  → 点击“开始演示”
  → 公共开场视频自动播放
  → 视频结束并冻结最后一帧
  → 四选一覆盖层
  → 点击选项并锁定
  → 1 秒路线确认卡
  → 对应分支视频
  → 结果卡
      ├─ 选择其他路线：返回四选一，不重播开场
      └─ 重新开始：回到启动页
```

选择页和结果页不使用倒计时自动跳转，防止老师讲解时页面自行变化。

## 5. 页面组成

### 电影画面层

- 16:9 视频居中铺满主要区域，桌面端优先。
- 开场和分支视频使用同一个播放器组件。
- 切换视频时使用短暂黑场或路线确认卡，隐藏素材间的视觉跳变。

### 状态 HUD

始终显示四项：剩余天数、左手状态、天气、矿权状态。分支视频播放完后按照选择更新。

### 选择覆盖层

四个按钮直接覆盖在冻结尾帧底部，每个选项只展示：路线名称、预计时间和一句核心风险。不要模拟票数，避免老师误以为已经实现多人投票。

### 结果卡

结果卡展示：

- 选择名称与决策类型；
- 三项状态变化；
- 一句战略取舍解释；
- “选择其他路线”和“重新开始”两个操作。

## 6. 数据与组件边界

剧情数据独立放在一个配置文件中：

```ts
type RouteOption = {
  id: 'A' | 'B' | 'C' | 'D'
  label: string
  decisionType: string
  timeHint: string
  riskHint: string
  video: string
  resultTitle: string
  resultSummary: string
  metrics: {
    days: string
    safety: string
    claim: string
  }
}
```

页面状态只保留：

```ts
type DemoPhase = 'launch' | 'intro' | 'choice' | 'route' | 'result'
```

组件分为：启动页、视频舞台、HUD、选择层、路线确认卡、结果卡。视频路径和结果文案不得散落在 React 组件里。

## 7. 视频文件约定

```text
public/videos/demo/
  intro.mp4
  route-a-wait.mp4
  route-b-mountain.mp4
  route-c-valley.mp4
  route-d-forecast.mp4
```

Pavo 成片尚未齐全时，可用现有视频作为明确标注的临时占位；替换正式成片时保持文件名不变，Web 无需改代码。

## 8. 异常处理

- 视频加载失败：显示“视频素材待替换”，同时允许进入对应结果卡和返回选择页。
- 分支视频播放结束：只进入对应结果，不自动重开。
- 连续点击选项：第一次点击后立即锁定，防止同时触发多个视频。
- 浏览器自动播放受限：启动页由用户点击开始，之后视频均由该交互链触发。

## 9. 验收标准

1. 开场结束后稳定显示四个选择。
2. A/B/C/D 每个按钮只播放自己对应的视频。
3. 四条路线结束后显示不同的结果文案和指标。
4. “选择其他路线”无需重播开场即可体验其他分支。
5. 视频缺失时页面不崩溃，仍可查看结果和返回。
6. 1440×900 桌面窗口下无横向滚动、遮挡或文字溢出。
7. `npm run typecheck`、`npm test -- --run` 和 `npm run build` 通过。

## 10. 后续扩展接口

老师认可 Demo 后，再把每个 `RouteOption` 的结果节点替换成下一轮选择即可。扫码投票、班长权重和决策报告均作为独立阶段追加，不影响本轮视频播放器和路线数据结构。
